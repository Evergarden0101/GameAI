## 1. “游戏 AI”到底指什么 <a id="sec1"></a>

游戏 AI **不是**学术意义上的 AI。它的目标很少是“把游戏玩到最优”，而是让游戏
**有趣、可信、且高性能**。国际象棋引擎追求获胜；而潜行游戏里的守卫，目标却是
“**以一种有趣的方式输掉**”，好让玩家觉得自己很聪明。几乎每个决策都受三条约束
的影响：

- **可信优先于最优。** 永远打不空的敌人并不好玩。游戏 AI 有很大一部分是被
  **刻意削弱**的智能。
- **实时性能。** 决策必须塞进 16 毫秒一帧（60 FPS）的一小片时间里，而且常常
  要在成百上千个智能体之间分摊。
- **设计师可控。** 设计师必须能够编写、调参并**预测**行为。这正是为什么透明的
  技术（状态机、行为树）主导了数十年，至今仍驱动着绝大多数上线的游戏。

正因如此，“经典”的手工编写技术从未退场。“现代”的学习型技术是**增量式**的补充
——在特定问题上非常强大，但会牺牲设计师所看重的可控性与可预测性。

## 3. 经典游戏 AI <a id="sec3"></a>

### 3.1 NPC —— 有限状态机与行为树 <a id="sec31"></a>

非玩家角色（守卫、村民、敌人、同伴）是游戏 AI 的日常主力。两种手工编写技术占据
主导地位。

**有限状态机（FSM）。** 智能体在任一时刻只处于一个**状态**（`巡逻`、`调查`、
`追击`、`攻击`、`逃跑`）。**事件**——看到玩家、听到声响、受到伤害——触发状态之间
的**转移**。FSM 简单、可预测、极易调试，这正是设计师钟爱它的原因。

**行为树（BT）。** 当角色变复杂时，扁平 FSM 会遭遇“转移爆炸”（每个状态都要连到
其他所有状态）。行为树改用 **序列（Sequence，按顺序全部执行）** 和
**选择（Selector，逐个尝试直到成功）** 节点，把小行为组合成一棵每帧重新求值的树。
行为树的可扩展性好得多，在《光环 2》（2004）之后成为 3A 标准。

**具体案例**
- 《吃豆人》（1980）：每个幽灵都是一个带鲜明个性的微型 FSM——Blinky 直接追，
  Pinky 瞄准你的前方，Inky 行为诡异，Clyde 靠近时反而撤退。用极简规则做出
  **可信行为**的典范。
- 《F.E.A.R.》（2005）：以其 **GOAP** 规划器（见 3.5）闻名，叠加在状态逻辑之上，
  让士兵涌现出包抄与压制。
- 《光环》系列：为步兵 / 精英兵使用带士气与撤退的行为树。

**用途。** 几乎任何 NPC 或敌人的默认选择：守卫、野生动物、同伴、Boss。廉价、
可编写、可预测。

**局限。** 纯反应式——不会学习，也没有长期规划。大型 FSM 会变成一团乱麻；大型
行为树则会又深又难以推理。行为的好坏完全取决于设计师的预见，聪明的玩家很快就能
摸清并利用固定套路。

▶ **示例：** [`samples/npc/npc_fsm.py`](../samples/npc/npc_fsm.py) —— 一个守卫
仅凭感知和血量就在 巡逻 → 调查 → 追击 → 攻击 → 逃跑 → 巡逻 之间流转，另附一个
用行为树实现“是否该攻击”的紧凑版本。

### 3.2 集群 / 蜂群敌人 —— 集群行为（Boids） <a id="sec32"></a>

当大量小型敌人需要作为一个协调整体移动时——蝙蝠、老鼠、虫族、鱼群、无人机云
——经典答案是 Craig Reynolds 的 **Boids**（1986）。每个智能体只用其**局部**邻居，
遵循三条规则转向：

1. **分离（Separation）**——避开拥挤（防止碰撞）。
2. **对齐（Alignment）**——朝邻居的平均朝向转向。
3. **聚合（Cohesion）**——朝邻居的平均位置转向（保持成群）。

再加上第四条朝向玩家的**寻的（seek）**规则，蜂群就会**作为一个整体进行猎杀**。
关键在于**没有中央控制器**：群体那种协调的观感，是众多智能体遵循相同局部规则后
**涌现**出来的——既廉价又自然。

**具体案例**
- 《半衰期》（1998）为飞行生物使用了 boids；无数 RTS 游戏用集群让编队自然移动而
  不是相互重叠。
- 《蝙蝠侠：阿卡姆》系列用集群表现成群的蝙蝠。
- 现代引擎提供转向行为系统（分离、抵达、游荡、逃离），叠加在寻路之上混合。

**用途。** 廉价敌人群或环境生物；人群模拟；编队。与一个被群体跟随的寻路“队长”
配合得天衣无缝。

**局限。** 涌现行为难以精确编写——你只能调权重然后**祈祷**。朴素实现是 O(n²)
（每个智能体都要检查其他所有智能体），因此大群需要空间划分（网格、四叉树）。
Boids 本身不会避墙，通常要与寻路或避障混合使用。

▶ **示例：** [`samples/flocking/flocking.py`](../samples/flocking/flocking.py)
—— 40 个 boid 仅凭局部规则自组织并逼近玩家。

### 3.3 追踪 / 追击敌人 —— 寻路（A\*） <a id="sec33"></a>

“追踪敌人”必须**绕过障碍**去够到一个移动目标。主力算法是 **A\***
（“A 星”，Hart–Nilsson–Raphael，1968），一种最佳优先图搜索，每次扩展使下式最小
的节点：

```
f(n) = g(n) + h(n)
```

其中 `g` 是从起点到该节点的已知代价，`h` 是到目标的**启发式**估计（如曼哈顿或
欧氏距离）。若 `h` 从不高估（即**可采纳**），A\* 保证找到最短路径。游戏在网格、
路点图，或描述可行走多边形的**导航网格（nav-mesh）**上运行 A\*。

**追击移动目标**就是 A\* 加上一条“**何时重新规划**”的策略：每帧重算（简单但昂贵）、
定时重算，或仅在目标移动足够远时重算。分层寻路和流场（flow field）可将其扩展到
数百个单位。

**具体案例**
- 几乎所有带导航的游戏：《星际争霸》《帝国时代》、塔防小怪、潜行游戏中返回岗位
  的守卫。
- 《吃豆人》幽灵（又是它）——一种极简的网格追击，甚至不需要完整 A\*。
- 导航网格是 Unity（NavMesh）和 Unreal（导航系统）的标准配置。

**用途。** 任何需要穿过复杂地图抵达某点的智能体：追击者、巡逻兵、跑腿任务同伴、
RTS 单位指令。

**局限。** 代价随地图大小和智能体数量增长；为许多追击者朴素地每帧重算非常昂贵。
动态障碍（门、其他智能体）需要重规划或局部避障。网格 A\* 生成“方块状”路径，通常
需要平滑处理。跨越巨大世界的远程规划需要分层方法。

▶ **示例：** [`samples/follow/pathfinding_astar.py`](../samples/follow/pathfinding_astar.py)
—— 敌人先绕过一堵墙抵达固定目标，然后通过每帧重算 A\* 路径来追击逃跑的玩家。

### 3.4 赛车 AI —— 路点、转向与橡皮筋难度 <a id="sec34"></a>

赛车对手结合了三种思想：

1. **以路点表示赛车线。** 赛道上标注一串路点（或样条曲线），构成理想线路。AI 使用
   **纯追踪 / 前视（pure-pursuit / look-ahead）** 控制器：始终朝稍前方的一个点转向。
2. **转向与速度控制（PID）。** 比例控制器让方向盘转动量与航向误差成正比；刹车点与
   过弯速度让车在急弯前减速、在直道上全油门。
3. **橡皮筋难度（动态难度调整，DDA）。** 为了让比赛保持胶着，AI 落后时上调其最高速度，
   领先过多时下调。这套“追赶”逻辑，正是《马力欧卡丁车》和许多街机赛车（有时颇具
   争议）的秘密。

**具体案例**
- 《马力欧卡丁车》系列——公开的橡皮筋机制与追赶道具。
- 《极限竞速》**Drivatar**——机器学习出的驾驶画像，模仿**真实玩家**的风格（这是 ML
  在上线赛车游戏中一次早期而著名的应用；见 4.3）。
- 《GT 赛车 Sophy》（索尼 AI，2022）——一个击败顶尖人类车手的**强化学习**智能体
  （见 4.1）。赛车正是经典与现代 AI 交汇之处。

**用途。** AI 对手、幽灵圈速、交通车流，以及赛车 / 驾驶游戏中的“自动驾驶”辅助。

**局限。** 纯路点 AI 的水平完全取决于其编写的线路，遇到意外地形（打转的车、抄近道）
可能显得机械或失灵。橡皮筋若过于激进，会让人觉得不公平（“AI 在作弊”）。真实的超车、
封堵与考虑物理的驾驶很难手工编写——这恰恰是为什么前沿（Sophy、Drivatar）转向了学习。

▶ **示例：** [`samples/racing/racing_ai.py`](../samples/racing/racing_ai.py)
—— 一个带 PID 转向和橡皮筋机制的路点跟随 AI，与一个匀速“玩家”比赛，并把差距保持得很小。

### 3.5 其他经典技术（GOAP、效用 AI、MCTS、PCG） <a id="sec35"></a>

- **GOAP（面向目标的行动规划）。** 不再硬编码状态转移，而是赋予智能体**目标**以及
  **带前置条件 / 效果的行动**，由规划器（在行动空间上跑 A\*）在运行时拼装出计划。
  在《F.E.A.R.》（2005）首次亮相；能产生灵活、涌现的战术。
- **效用 AI（Utility AI）。** 每个可能行动由一个关于世界状态的**效用**函数打分；
  智能体选取最高分（或按分数抽样）。非常适合有多种竞争性需求的智能体——最著名的是
  《模拟人生》（2000），小人会权衡饥饿、娱乐、社交、卫生等。
- **棋类 / 策略游戏的搜索。** 带 *alpha-beta 剪枝* 的 *Minimax* 驱动了经典国际象棋
  引擎；*蒙特卡洛树搜索（MCTS）* 驱动了强大的围棋 / 棋类 AI，后来在 AlphaGo 中与
  深度学习融合。
- **程序化内容生成（PCG）。** 用算法生成关卡、地图、地牢、掉落与地形：《Rogue》
  （1980）、《Spelunky》、《我的世界》、《无人深空》（1800 亿亿颗星球）。如今越来越多
  与 ML（“PCGML”）以及生成式模型混合。

## 4. 现代游戏 AI <a id="sec4"></a>

现代方法从数据或经验中**学习**行为，而不是手工编写。它们在手工编写不切实际的地方
大放异彩，但代价是数据、算力与可预测性。

### 4.1 强化学习（RL）智能体 <a id="sec41"></a>

在 **RL** 中，智能体通过试错来最大化累积**奖励**。它构建一个把状态映射到动作的
*策略*，由来自环境的反馈引导。表格型 **Q-learning** 的更新式是经典起点：

```
Q(s,a) ← Q(s,a) + α · [ r + γ · maxₐ' Q(s',a') − Q(s,a) ]
```

`α` 是学习率，`γ` 折扣未来奖励。把表格换成神经网络，就得到 **深度 Q 网络（DQN）**；
像 **PPO** 这样的策略梯度方法，以及 **自我对弈**（智能体与自己的副本对练）驱动了那些
标志性成果：

**具体案例**
- **AlphaGo / AlphaZero / MuZero**（DeepMind，2016 至今）——RL + MCTS 击败围棋世界
  冠军，随后仅凭自我对弈掌握国际象棋与将棋。
- **OpenAI Five**（2019）——五个 PPO 训练的智能体在《Dota 2》——一个长时程、
  不完全信息的团队游戏——中击败了世界冠军。
- **AlphaStar**（DeepMind，2019）——在《星际争霸 2》中达到宗师段位。
- **GT 赛车 Sophy**（索尼 AI，《自然》2022）——一个跑赢全球顶尖《GT 赛车》车手、
  并具备拟人化车技的 RL 智能体。
- **Unity ML-Agents**——让工作室在自家游戏中训练 RL / 模仿学习智能体的工具包。

**用途。** 超人或高度自适应的对手；为过于复杂而无法脚本化的游戏（赛车物理、
RTS/MOBA 微操）打造智能体；自动化试玩与平衡性测试；NPC 技能调优。当你拥有一个
快速的模拟器和清晰的奖励时最合适。

**局限。**
- **样本饥渴且昂贵。** OpenAI Five 每天要训练相当于数百年的游戏时长；多数工作室
  负担不起这样的算力。
- **奖励设计困难。** 糟糕的奖励函数会导致*奖励作弊*——智能体钻空子，而非“正常”地玩。
- **不可预测且难以调试。** 学到的策略是一个黑箱；你很难保证它不会做出荒唐的事，
  而这正是设计师所反感的。
- **常常太强。** 超人机器人并不好玩；你必须**刻意削弱**它。对未见过的情境与内容
  泛化能力差也很常见。
- **集成成本高。** 需要训练管线、模拟器和细致的 QA——相比状态机是一项重活。

▶ **示例：** [`samples/rl/q_learning.py`](../samples/rl/q_learning.py) —— 一个表格型
Q-learning 智能体仅凭奖励就发现穿越迷宫（并避开陷阱）的最优路径，然后打印出学到的策略。

### 4.2 生成式 AI 智能体（LLM 驱动） <a id="sec42"></a>

最新的类型把一个**大语言模型（LLM）**置于 NPC 或智能体的核心。角色不再依赖固定的
对话树，而是拥有：

- **人设**（定义它是谁的系统提示词），
- **记忆**（对话历史，有时还包括长期记忆库），以及
- **工具 / 函数调用**，让它的话语转化为真实的游戏动作——发布任务、开启商店、改变
  好感度、移动、攻击。

玩家可以说**任何话**，NPC 都能符合人设地回应并作用于世界。再把许多这样的智能体放进
一个共享世界，**涌现式社交行为**便会出现。

**具体案例**
- **《生成式智能体》**（Park 等人，斯坦福，2023）——沙盒小镇“Smallville”里的 25 个 LLM
  智能体建立关系、传播消息，并自发地组织了一场情人节派对。这是奠基性的演示。
- **NVIDIA ACE**、**Inworld AI**、**Convai**——把 LLM 驱动、带语音的 NPC 带入真实游戏
  引擎的中间件。
- **AI Dungeon**（2019）——一款早期由 GPT 驱动的开放式文字冒险。
- 生成式模型也用于**内容**：贴图、对话、任务与关卡（生成式 PCG）。

**用途。** 开放式、可反复游玩的对话；动态任务；有个性和记忆的同伴；角色的快速原型；
无障碍设计（用自然语言与 NPC 交谈）。作为**设计工具**（离线生成内容）同样强大。

**局限。**
- **幻觉与一致性。** LLM 会编造事实、破坏世界观设定，或与先前的说法自相矛盾——这对
  正史与叙事很危险。
- **可控性与安全。** 自由生成的输出可能跑调、被玩家利用（“越狱”），或说出工作室从未
  批准的话。护栏与工具约束必不可少；要用工具**限定 LLM 的权限边界**。
- **延迟与成本。** 每句话都要一次网络往返，增加延迟；按 token 计费在规模化时累积可观；
  端侧模型则以质量换速度。
- **确定性与测试。** 非确定性输出难以 QA，也难以为 bug 报告复现。
- **落地（Grounding）。** LLM 必须通过工具 / 记忆绑定到真实游戏状态，否则它只是没有
  玩法后果的闲聊。

▶ **示例：**
[`samples/generative/generative_npc.py`](../samples/generative/generative_npc.py)
—— 一个 LLM 铁匠（Anthropic 的 Claude，`claude-opus-5`）既即兴生成符合人设的对话，
**又**通过工具调用（发布任务、查看库存、调整好感度）驱动真实游戏状态。未设置 API
密钥时会运行一个完全离线的模拟，因此你可以零配置地研究其架构。

---

### 4.3 其他机器学习方法 <a id="sec43"></a>

- **模仿 / 行为克隆。** 训练模型从录制的数据中复制**人类**的玩法。**《极限竞速》的
  Drivatar** 学习每位玩家个人的驾驶风格，于是你朋友的“幽灵”即便在离线时也能参赛
  ——无需超人 RL 就能得到拟人化对手。
- **用于感知 / 动画的监督学习。** 学习型动画控制器（动作匹配、学习式移动）、难度预测、
  匹配、作弊检测与玩家流失模型都是不碰“AI 对手”、却塑造体验的机器学习。
- **混合系统**是务实的前沿：用行为树搭结构，用效用打分做决策，用学习型子策略处理困难
  的运动技能，用 LLM 处理对话——每种技术都用在它最擅长之处。

## 5. 如何选择方案 <a id="sec5"></a>

| 如果你需要…… | 就选用 | 原因 |
|--------------|--------|------|
| 行为清晰、可编写的守卫 / 敌人 | **FSM / 行为树** | 可预测、廉价、设计师可控 |
| 自然移动的群体 | **集群 / 转向** | 涌现式协调，无中央大脑 |
| 穿过地图抵达某点 | **A\* / 导航网格** | 最优、成熟 |
| 可信的赛车对手 | **路点 + PID + 橡皮筋** | 在编写线路上做出胶着、有趣的比赛 |
| 复杂的反应式战术 | **GOAP / 效用 AI** | 由目标 / 分数涌现出计划 |
| 超人或无法脚本化的技巧 | **强化学习** | 学到你写不出来的东西——但有代价 |
| 从数据得到拟人化对手 | **模仿学习** | 复制真实玩家的风格 |
| 开放式对话与涌现式角色 | **生成式 / LLM 智能体** | 符合人设地说 / 做任何事 |

**经验法则：** 从满足设计目标的**最简单**技术起步。只有当手工编写确实不切实际时，
才动用学习型方法；并且始终用工具与校验来**限定生成式智能体的权限**。
