# 第一部分——基础

## 1. 游戏 AI 是什么（不是什么）

当研究者说“AI”时，通常指构建一个把问题解得*尽可能好*的系统——一个能赢的国际象棋引擎、一个准确的分类器、一个高效抵达目标的机器人。**游戏 AI 不同，而这份不同正是本书的主题。** 游戏里 AI 的目标不是获胜，而是让*玩家*玩得开心。

一个总能立刻找到你的潜行游戏守卫，会在几秒内结束游戏，感觉糟透了。一个开出物理完美圈速的赛车对手，会消失在地平线尽头再也见不到。一个只要你进入其视线、就以完美精度在任意距离即刻命中的射击敌人，纯粹地不公平。在每一种情形里，AI 玩得越“好”，游戏就越糟。所以游戏 AI 首先是一门艺术：**构建被刻意塑形、约束、常常还被削弱的智能**，以营造一种特定的体验。

三条约束压在游戏 AI 程序员几乎每一个决策之上：

**1. 可信优先于最优。** AI 必须*看起来*聪明，这与*真的*聪明并不相同。玩家会把意图读进行为里：一个懂得进掩体、喊出“我在包抄”、并扔手雷的敌人*感觉*很聪明，即便底层只是遵循几条简单规则。反过来，一个做着真正聪明、玩家却察觉不到的事的智能体，是浪费的算力。这门手艺的大半在于**“预告（telegraphing）”**——通过动画、语音提示与可读的移动，让 AI 的推理清晰可见。

**2. 实时性能。** 一个以每秒 60 帧运行的游戏，每帧只有约 **16 毫秒**去模拟*一切*——物理、动画、渲染、音频，以及可能成百上千个智能体的 AI。一款 RTS 可能同时有上千个单位在寻路。正是这条硬预算，使得轻量、可预测的技术占据主导，也使得昂贵方法（深度神经网络、大规模搜索）只能被节制地使用、预计算，或跨多帧摊销。

**3. 设计师可控。** 游戏是被“作者化”的体验。设计师需要能搭建一个特定遭遇、调试它、预测它，并在测试者报告“Boss 卡在墙角”时把问题修好。这正是透明、可检视的技术——状态机、行为树——主导了数十年、至今依旧的安静原因：一个你无法预测的系统，就是一个你无法自信发布的系统。

正因这些约束，“经典”的手工编写技术从未退场。激动人心的“现代”学习型技术（强化学习、LLM 智能体）是**增量式**的补充：在手工编写不切实际的特定问题上非常强大，但恰恰牺牲了设计师所珍视的可控性与可预测性。一个成熟的游戏 AI 工程师把这一切视为同一个工具箱，并选用能产生目标手感的*最简单*工具。

> **核心区别。** *学术 AI 问“我如何赢 / 解决这个？”；游戏 AI 问“我如何让人类享受与它对抗或并肩的过程？”* 记住这一点，本领域那些奇特的选择——故意打空的敌人、会橡皮筋追赶的对手、带脚本“预告”的 Boss——就都说得通了。

## 3. 智能体循环：感知、思考、行动

几乎每个游戏智能体，从吃豆人幽灵到 Sophy 赛车手，每一“帧”（更新步）都运行着同一个循环：

```
        ┌─────────────────────────────────────────┐
        │                                          │
        ▼                                          │
   ┌─────────┐      ┌──────────┐      ┌─────────┐  │
   │  感知    │ ──▶ │  思考     │ ──▶ │  行动    │ ─┘
   │ 收集世界 │      │ 决定下一 │      │ 移动、  │
   │  状态    │      │ 步做什么 │      │ 射击、  │
   │         │      │          │      │ 建造…   │
   └─────────┘      └──────────┘      └─────────┘
```

- **感知**——读取智能体被允许知道的那部分世界：玩家位置（若可见）、附近掩体、自身血量、声响。关键是，好的 AI 会*限制*自己的感知，只用公平的信息——敌人不应对它看不见的玩家做出反应，否则幻觉破灭。
- **思考**——运行一个决策算法来选择行动。**本书的技术都活在这个方框里。** 状态机、行为树、效用打分、A\* 搜索、神经网络——都只是实现“思考”的不同方式。
- **行动**——把选定的动作作用于世界：设定移动目标、开火、排产一栋建筑。动作通常要跨很多帧才能完成，因此这个循环是连续的，而非一次性的。

后文的一切，本质上都是实现**思考**方框的方法目录——以及一份“哪种活儿选哪种”的指南。

# 第二部分——经典工具箱

第二部分的技术都是**手工编写**的：由人类设计师直接指定行为。它们廉价、可预测、易调试，而且在发明数十年后，仍是几乎每一款上线游戏的中坚。掌握这些，你就能构建有史以来大多数游戏的 AI。

## 4. 决策一——有限状态机与行为树

### 思想

角色 AI 最根本的问题是：*在当前处境下，我现在该做什么？* 最古老、最透明的答案是**有限状态机（FSM）**。

FSM 说：智能体在任一时刻只处于一个**状态**——`巡逻`、`调查`、`追击`、`攻击`、`逃跑`——而**事件**（看到玩家、听到声响、受到伤害、血量过低）触发状态之间的**转移**。就这么简单。每个状态定义行为（“在`巡逻`中沿路点行走”），转移定义逻辑（“若看到玩家，转到`追击`”）。

FSM 简单、可预测、极易调试——这正是设计师钟爱它的原因。你能在白板上把它画出来；当测试者说“守卫做了怪事”时，你能指出确切负责的那个状态和那条转移。

### FSM 撞上的问题，以及行为树

随着角色变复杂，FSM 有一个致命缺陷：**转移爆炸**。有 *n* 个状态，最多可能需要 *n×(n−1)* 条转移——每个状态都潜在地需要连到其他每个状态。到十几个状态时，这就变成一团无法维护的意大利面。

由《光环 2》（2004）发扬光大的**行为树（BT）**解决了这一点。BT 不是“状态加转移”的图，而是一棵**每帧从根重新求值的行为之树**。它的威力来自几种节点类型：

- **序列（Sequence，→）**：从左到右运行各子节点；全部成功才成功；遇到第一个失败即停止。（“进掩体 **并且** 瞄准 **并且** 开火。”）
- **选择（Selector，?）**：从左到右尝试各子节点；在*第一个*成功处成功。（“攻击 **否则** 追击 **否则** 巡逻。”）这天然给出**兜底 / 优先级**行为。
- **叶**节点是**动作**（做某事）或**条件**（测某事）。
- **装饰器**修饰一个子节点（取反、重复、加冷却）。

因为整棵树每帧重跑，一个更高优先级的分支（战斗）会在其条件一旦为真时自动**抢占**较低优先级的分支（巡逻）——无需显式转移。行为树可扩展到成百上千个行为，是模块化的（子树可复用），并成为角色 AI 的 3A 标准。

### 具体游戏

- **《吃豆人》（1980）**——FSM 的典范。每个幽灵都是一个带鲜明*目标选择个性*的极简状态机：Blinky 直接追你，Pinky 瞄你前方以拦截，Inky 用一个经 Blinky 反射的向量做诡异的钳形，Clyde 只在远时追、近时撤退。四条一行规则涌现出*感觉*像协同猎杀队的行为。本章的姊妹主题在后文详解，下方也有可运行代码。
- **《光环》系列**——为步兵和精英兵使用带士气（步兵首领死后会逃跑）的行为树。
- **《F.E.A.R.》（2005）**——在状态逻辑*之上*叠加 GOAP 规划器（第 5 章），成就其著名士兵。

### 用途

几乎任何 NPC 或敌人的默认选择：守卫、野生动物、同伴、Boss、简单敌人。若拿不准用什么，就从这里开始。简单智能体（少数几个状态）用 FSM；行为变复杂、或想要可复用的优先级逻辑时用行为树。

### 局限

纯**反应式**——没有前瞻或规划；智能体只做当前状态 / 树所说的，仅此而已。大型 FSM 变成意面；大型行为树变得又深又难追踪。最重要的是，行为的好坏完全取决于设计师的预见：聪明的玩家很快就能摸清并利用固定套路。长期推理需要规划（第 5 章）；适应性需要学习（第四部分）。

## 5. 决策二——效用 AI 与 GOAP

FSM 与行为树*做反应*。另外两种经典技术让智能体能**权衡选项**并**提前规划**。

### 效用 AI

效用 AI 不用硬规则，而是用一个关于当前世界状态的**效用函数**给每个可能动作打分，然后选最高分（或按分数比例抽样以增加变化）。每个动作都用一个数字回答“我此刻有多值得做？”。

这非常适合需要在**多种竞争性需求**间权衡的智能体。典范是**《模拟人生》（2000）**：每个小人持续地针对需求（饥饿、精力、娱乐、社交、卫生、如厕）为动作打分，做当前得分最高的事。饿了吃、困了睡、寂寞了找人——行为看起来很像真人，因为它*就是*一种持续的取舍，恰如真实的动机。

效用 AI 在策略游戏里同样出彩。在《文明》这类 4X 游戏中，一座城市会为它能建造的一切——移民者、工人、士兵、图书馆、粮仓——针对帝国当前处境打分（城市少？偏好移民者；受威胁？偏好军事；和平且发展？偏好基础设施）。没有决策树，只有一袋可调的打分函数。我们将在第 12 章构建这套东西。

**优点：** 平滑地处理多种因素，产生细腻的“视情况而定”的行为，添加新选项很容易（只需写它的打分）。**缺点：** 调打分函数是门玄学——一个权重不当的项就会导致古怪选择；而且因为一切都在混合，很难保证在某个特定情形下产生某个特定行为。

### GOAP——面向目标的行动规划

**GOAP** 又是一次不同的跃迁：你不再编写*行为*，而是编写*目标*以及*带前置条件与效果的行动*，让一个**规划器在运行时拼装出行为**。这相当于给某人一个目标和一箱工具，而不是一份脚本。

- 一个**目标**是期望的世界状态，例如 `enemy_dead = true`。
- 每个**行动**有**前置条件**（运行所需的世界状态）与**效果**（它如何改变世界），以及一个**代价**。例如 `Attack` 需要 `weapon_loaded ∧ near_enemy`，产生 `enemy_dead`。
- 规划器在*世界状态空间*上跑 **A\***（第 7 章），把行动从当前状态串联到满足目标的状态，最小化总代价。

其魔力在于**同一批行动会随世界变化重规划出不同的行为**。没枪？计划变成 *去武器处 → 拾取 → 装弹 → 接近 → 攻击*。已持枪？*接近 → 攻击*。没手雷来驱赶敌人？*无解*，于是智能体退回到别的目标。这些分支没有一个是被编写的——它们从行动定义里*涌现*出来。

GOAP 在**《F.E.A.R.》（2005）**首次亮相，至今仍是标杆：其士兵能把玩家从掩体后驱赶出来、包抄、协同压制，全部来自一套紧凑的行动集加一个规划器。玩家发誓 AI 在“作弊”，只因它太善于适应；其实它只是在重规划。

**用途：** 情形变化太多、无法逐一编写组合的敌人与 NPC——战斗 AI、沉浸式模拟角色、会使用工具与环境的智能体。**局限：** 规划比行为树更耗 CPU（通过不频繁规划并缓存来缓解）；设计一套干净、正交的行动集很难；而且涌现行为虽灵活，却比一棵编写好的树更难*保证*。

- [`samples/classic/goap_planner.py`](../samples/classic/goap_planner.py)——一个 F.E.A.R. 式士兵，目标是“消灭敌人”，由 A\* 在世界状态上求解。看它在未持枪时给出长计划、已持枪时给出短计划、当世界使目标无法达成时*无解*——纯粹的运行时重规划。

## 6. 移动一——转向与集群

决定*做什么*只是一半；智能体接着必须令人信服地*移动*。经典移动工具箱始于 Craig Reynolds 的**转向行为（steering behaviors）**——一些小而可组合的规则，每条产生一个转向力，混合成平滑、自然的运动：**寻的、逃离、抵达、追捕、闪避、游荡、避障。**

最著名的转向成果是**集群（flocking）**，或称 **Boids**（Reynolds，1986/87），移动一*群*简单智能体的标准方法——蝙蝠、老鼠、鱼、鸟、虫族、无人机云。每个智能体只用其**局部**邻居，遵循三条规则转向：

1. **分离**——避开拥挤（别碰撞）。
2. **对齐**——朝邻居的平均朝向转向。
3. **聚合**——朝邻居的平均位置转向（保持成群）。

再加上第四条朝向玩家的**寻的**规则，蜂群就会*作为一个整体猎杀*。关键洞见是**没有中央控制器**：整群那种协调、鲜活的运动，是众多各自遵循相同局部规则的智能体**涌现**出来的。这既廉价、可扩展又自然——与逐一编写每个单位截然相反。

**具体游戏：**《半衰期》（1998）为飞行生物使用 boids；无数 RTS 用集群让单位群自然移动而不重叠；《蝙蝠侠：阿卡姆》系列用集群表现成群蝙蝠；现代引擎（Unity、Unreal）内置转向行为系统，叠加在寻路之上混合。

**用途：** 廉价敌群、环境野生动物、人群、编队——通常与一个被群体跟随的寻路“队长”配合。**局限：** 涌现行为难以精确编写（你调权重然后祈祷）；朴素实现是 O(n²)，因为每个智能体都要检查其他所有智能体，因此大群需要空间划分（网格、四叉树）；而且 boids 本身不避墙——要与避障或寻路混合。

## 7. 移动二——A\* 寻路

一个“追踪 / 追击”敌人必须*绕过障碍*去够到目标。游戏导航的主力算法是 **A\***（“A 星”；Hart、Nilsson & Raphael，1968），一种既最优又高效的最佳优先图搜索。A\* 每次扩展使下式最小的节点：

```
f(n) = g(n) + h(n)
```

其中 **g(n)** 是从起点到 *n* 的已知代价，**h(n)** 是从 *n* 到目标剩余代价的**启发式**估计（网格上通常用曼哈顿距离，或直线距离）。若启发式从不*高估*真实剩余代价（即**可采纳**），A\* 保证找到最短路径——而且启发式越接近真实，扩展的节点越少。

游戏在三类图上运行 A\*：
- **网格**——最简单；每格是一个节点。产生“方块状”路径，通常需要平滑。
- **路点图**——手工或自动放置、由可行走链接相连的节点。
- **导航网格（navmesh）**——现代标准：把可行走地面分解为凸多边形，于是路径在少数几个大区域上求得，而非数千个小格。Unity 的 *NavMesh* 与 Unreal 的*导航系统*都基于 navmesh。

**追击移动目标**就是 A\* 加一条*重规划策略*：每帧重算（简单但昂贵）、定时重算，或仅当目标移动足够远时重算。对成百上千个单位，工作室使用**分层寻路**（先在区域上规划，再在区域内规划）与**流场**（计算一张整支军队都跟随的方向场）。

**具体游戏：** 基本上所有带导航的游戏——《星际争霸》《帝国时代》、塔防小怪、返回岗位的潜行守卫、开放世界同伴。**用途：** 任何必须穿过复杂地图抵达某点的智能体。**局限：** 代价随地图大小与智能体数量增长；为许多追击者朴素地每帧重算非常昂贵；动态障碍（开门、其他单位）需要重规划或局部避障；网格路径需要平滑才自然。

## 8. 博弈搜索——Minimax、Alpha-Beta 与 MCTS

对于**双人、完全信息**的游戏——国际象棋、跳棋、四子棋、围棋、井字棋——经典 AI *搜索博弈树*：它前瞻可能的着法、应着及其后果。

### Minimax 与 Alpha-Beta

**Minimax** 假设双方都最优。一方（MAX）试图最大化局面分值；对手（MIN）试图最小化。算法递归地把着法探索到某个深度，评估所得局面，再把值沿树回传——MAX 取最高、MIN 取最低——以选出通往最佳有保证结局的着法。

难点在于博弈树会爆炸：国际象棋每步约 35 种合法着法，前瞻 *d* 步就是约 35^d 个局面。**Alpha-Beta 剪枝**是必备优化：它跟踪每一方已经确保的最好分值（MAX 用 α，MIN 用 β），并**剪掉**任何不可能改变决策的分支。它返回与朴素 minimax *完全相同*的答案，却常常只探索少一个数量级的节点——在我们的井字棋示例里，alpha-beta 把节点数削减了 **约 96%**。**深蓝**——1997 年击败国际象棋世界冠军卡斯帕罗夫——正是运行在定制硬件上、带手工评估函数的 alpha-beta minimax。

### 蒙特卡洛树搜索（MCTS）

对于大到无法深搜、或难以写出好评估函数的游戏（著名的**围棋**，每步约 250 种着法、10^170 个局面），minimax 会卡住。**MCTS** 改用**采样**取胜。它重复四步数千次，长出一棵不对称的树：

1. **选择**——从根出发，用 **UCB1**（一个平衡*利用*已表现好的着法与*探索*少被尝试的着法的公式）下降到一个有希望的叶。
2. **扩展**——为一个未尝试的着法添加一个新子节点。
3. **模拟**——用*随机*着法把剩下的对局玩到底（“rollout”），得到胜 / 负 / 平。
4. **回传**——把该结果沿路径推回，更新每个节点的胜 / 访问统计。

预算用尽后，选择访问最多的着法。MCTS **不需要评估函数——只需规则**，并天然把精力集中在要紧的着法上。它是强大围棋程序的核心，并在与引导选择、替换随机 rollout 的深度神经网络融合后，成就了**《AlphaGo》**（2016）。

**用途：** 棋类、卡牌、回合制战棋，以及任何有可模拟结果模型的决策。**局限：** minimax 需要好的评估函数与对分支因子的克制；MCTS 需要大量模拟（算力）与快速模拟器，其纯形式在没有神经网络引导时难以应对极长对局或巨大分支。

## 9. 空间推理——影响力图与程序化内容

还有两种经典工具让工具箱完整。

### 影响力图

**影响力图**是覆盖在世界上的一张网格，每格存一个数字，概括“谁控制这片区域”。友军单位在附近格子盖上正影响并扩散；敌军盖上负影响；把它们求和。结果是一张廉价、可查询的战术态势图：

- **高友军值格** = 安全集结区。
- **零交叉线**（友军影响与敌军影响相遇处）= **前线**。
- **高敌军值格** = 危险；绕开它们。
- 用“目标可取性”图减去“威胁”图，就告诉一个单位*该去*哪里。

影响力图驱动 RTS 决策（从哪进攻、前线在哪、哪个基地薄弱）、FPS 战术定位（找敌军影响低的掩体），以及 MOBA / 策略的目标选择。它是一种空间效用打分——计算廉价、易于推理，在策略游戏里被大量使用。

### 程序化内容生成（PCG）

**PCG** 用算法*生成*内容——关卡、地图、地牢、掉落、地形、任务——而非手工摆放。它从**《Rogue》**（1980）与**《Spelunky》**的全随机地牢，到**《我的世界》**的噪声世界，再到**《无人深空》**（2016）那 1800 亿亿颗程序化生成的星球。技术包括随机布局文法、用于地形的 Perlin/Simplex 噪声、用于瓦片地图的波函数坍缩，以及日益增多的**机器学习式 PCG（PCGML）** 与生成式模型。PCG 以牺牲可控性换来近乎无限的内容与可重玩性——经典的张力在于生成不仅多样、还要*好*的内容，这正是大多数上线 PCG 会把生成与手工约束、精心设计的场景混合的原因。

## 10. 赛车 AI——从马力欧卡丁车到 GT 赛车 Sophy

赛车是同时看到经典与现代 AI 并列的绝佳类型，因为两款极为不同的赛车游戏正处于光谱两端：《马力欧卡丁车》的街机式混乱，与《GT 赛车》的仿真式精确。

### 经典赛车技术栈

几乎每个赛车对手，无论街机还是仿真，都由三层手工编写构建：

**1. 以路点（或样条）表示赛车线。** 赛道被标注上一串构成理想线路的点。AI 使用**纯追踪 / 前视**控制器：始终朝线路上稍前方的一点转向，从而产生平滑过弯。（看太近会抖，太远会切弯。）

**2. 转向与速度控制（PID）。** **比例控制器**让方向盘转动量与“我朝向哪”和“前视点在哪”之间的航向误差成正比。刹车点与各弯目标速度让车在急弯前减速、在直道上加速。更复杂的 AI 会加上积分与微分项（完整 PID）以及抓地力模型。

**3. 橡皮筋难度（动态难度调整，DDA）。** 为了让比赛刺激，AI 的表现会依据与玩家的差距被悄悄微调：落后就上调最高速度，领先就松油门。这套“追赶逻辑”让车队保持紧凑、终点值得拍照。

### 案例：《马力欧卡丁车》——乐趣胜过公平

《马力欧卡丁车》是**为乐趣而刻意不公平的 AI** 的典范。两套系统挑起大梁，且都与驾驶技术无关：

- **橡皮筋速度。** 落后的电脑卡丁车获得真实的最高速度加成；领先者被减速。无论你开得多好或多差，车队都被压缩，于是每场比赛都紧张到终点线。推得太过会显得廉价（“AI 作弊”），这正是调校如此微妙的原因。
- **按名次分配道具。** 这是精妙之处。你从道具箱里摇到的道具取决于你的**名次**，而非纯粹随机。领先者摇到弱的防御道具（香蕉、单个绿龟壳）；落后者摇到强力的**追赶道具**（三蘑菇、无敌星、火箭刺猬，以及臭名昭著、直扑第一名的**蓝 / 刺甲龟壳**）。这张道具表*就是*一套动态难度系统：它把翻盘工具交给需要的玩家，并否决遥遥领先者扩大优势的手段。

分配之上还有一个小小的**道具使用 AI**：有人在你身后逼近时把龟壳握在身后当盾；不在第一时就放蓝壳；把蘑菇加速留给抄近道。底层的驾驶 AI 可以相当简单，因为*道具*制造了戏剧性。

> **这一课：** 在街机赛车里，大部分“AI”根本不在驾驶上——而在一套被设计来制造接近、混乱、好笑比赛的道具经济里。

### 案例：《GT 赛车 7》/ **Sophy**——AI 学会了赛车

处于另一端的是仿真。数十年里，《GT 赛车》的内置对手都是经典路点跟随者——称职但机械，专家一眼看穿。真实的贴身缠斗——在抓地极限处选择何时刹车、如何守线、何时做出不致相撞的强行内切超车——被证明极难手工编写。

于是索尼 AI 转而去训练它。**GT 赛车 Sophy**（发表于《自然》，2022）是一个**深度强化学习**智能体（第 14 章），通过在海量模拟里程上试错学会开《GT 赛车》，奖励圈速、惩罚冲出赛道或碰撞。Sophy **击败了全球最优秀的 GT 车手**——而且值得注意的是，它学到的不只是纯粹的速度，还有**车技与体育精神**：战术性超车、封堵，以及遵守赛车礼仪（奖励被精心塑形以抑制脏动作）。后来一个版本被放进《GT 赛车 7》里可玩，于是普通玩家也能与一个超人级的学习对手同场竞技。

Sophy 是本书里最清晰的一个例子，说明*为什么*工作室转向学习：经典路点技术栈有一道手工编写无法突破的天花板，而 RL 突破了它。

### 也值得一提

- **《极限竞速》Drivatar**——一套**模仿学习**系统（第 15 章），从玩家录制的圈速中学习*每位真实玩家*的驾驶风格，于是你朋友的“Drivatar”即便离线也在你的游戏里参赛。拟人化，而非超人。

### 用途与局限

经典技术栈（路点 + PID + 橡皮筋）廉价、可控，至今仍装配在大多数赛车游戏里；其局限是线路看起来机械、遇到意外地形（打转的车、近道）会失灵、以及橡皮筋若过度会显得不公平。学习式车手（Sophy）达成超人级车技，但需要快速模拟器、庞大训练算力、精心的奖励塑形——而对一个*上线*对手，还要刻意削弱，好让它有趣而非令人沮丧。

- [`samples/racing/racing_ai.py`](../samples/racing/racing_ai.py)——经典技术栈：路点跟随、PID 转向与橡皮筋把与“玩家”的差距保持得很小。
- [`samples/racing/mario_kart_items.py`](../samples/racing/mario_kart_items.py)——六辆卡丁车带**按名次分配道具**与橡皮筋竞速；看落后者摇到蓝壳和星星来缩小差距，整个车队在几个车身内冲线。

## 11. 射击 AI——从 Doom 到彩虹六号与 Apex

第一人称射击推动了数十年的战斗 AI 创新。看它演进，就像看经典工具箱被一层层叠高。

### 谱系

**1993——《Doom》：状态机与视线。**《Doom》的怪物是纯有限状态机。每个都有 *空闲、行走、攻击、受伤、死亡* 等状态与简单转移。两个想法让它们远超其简单本身而有了生命：
- **视线与声音激活**——怪物在能看到玩家或听到枪声时“苏醒”，于是世界感觉是有反应的。
- **怪物内斗**——若一个怪物误伤了另一个（一发流弹），受害者会转而攻击攻击者。这条微小规则产生了玩家至今仍在利用的涌现混乱，几乎零成本。《Doom》是决定性的证明：**好手感来自简单规则加良好预告，而非复杂 AI。**（移动很粗糙——怪物基本朝玩家走、带基础避障，没有真正的寻路。）

**1998——《半衰期》：小队与战术的错觉。**《半衰期》的陆战队看似包抄、撤退、呼喊、协同。底层是一个带小队槽的日程 / 任务系统，但那种*被感知到*的战术智能是一次巨大飞跃——而它靠**语音提示**（“他在包抄！掩护我！”）驱动的程度，不亚于底层逻辑。这确立了**预告**为核心手艺：告诉玩家 AI 在做什么，他们就会赋予它超出实际的智能。

**2001–2004——《光环》：行为树与“30 秒的乐趣”。** Bungie 把《光环》敌人建在带分层行为、士气与载具的行为树上，围绕可重复、可读的战斗遭遇来调校。《光环 2》让行为树在业界普及。

**2005——《F.E.A.R.》：GOAP 与战斗 AI 的高水位线。** 被广泛视为那个时代最好的战斗 AI，《F.E.A.R.》的复制体士兵在一套**掩体系统**之上使用 **GOAP**（第 5 章）。给定目标“杀死玩家”与带前置条件 / 效果的行动，规划器涌现出**火力压制 + 机动包抄**：一名士兵**压制**（把玩家钉在掩体后），其他士兵**包抄**到新角度、扔手雷驱赶、暴露时撤退。关键在于士兵会把这一切*喊出来*（“包抄！”“压制！”），于是玩家把真正的战术读进了机械上其实是“规划器加掩体点选择”的东西里。这套压制—包抄循环是现代射击小队 AI 的内核。

**2015 至今——破坏、装备与大逃杀。**
- **《彩虹六号：围攻》**以其**全可破坏环境**定义自身：墙、地板、天花板都能被打穿，于是“掩体”与视线是动态的、由玩家创造的。设计挑战在于 AI（在“恐怖分子狩猎”/ 训练模式中），更重要的是必须对一个*中途改变形状*的空间做推理的关卡与装备系统——加固墙、破墙炸药、侦察无人机、可破坏的视线。这是地图本身作为变量的战术 AI。
- **《Apex 英雄》**等大逃杀射击以 PvP 为主，因此其值得注意的“AI”不同：**面向新手的机器人**，加上瞄准、移动与匹配周边的系统。（该工作室早先的《泰坦陨落》以“步兵”AI 作为让玩家感到强大的炮灰。）更广的大逃杀潮流也复活了 **AI 导演**的概念——见下文。

**2008——《求生之路》：AI 导演。** 值得特别一提，因为它重新定义了游戏 AI *是什么*。Valve 的 **AI 导演**不是对手，而是一个隐形的**编剧**——观察玩家的压力，动态编排体验节奏（生成尸潮、分配血包与弹药、安排低谷与高潮），让每次游玩都紧张而公平。这是作为*叙事*的动态难度，影响了此后无数游戏的节奏系统。

### 到底是什么驱动射击 AI

剥开上述任何一个，你会发现同一套来自第二部分的技术栈：
- **视线**检查（我能看到目标吗？）——几乎每个决策的闸门。
- **掩体选择**——按能多好地遮挡敌方视线为附近位置打分（效用 / 影响力）。
- **压制**——一名士兵开火以*钉住*目标，降低其效能并迫使其脱离视线。
- **小队协同**——分工（锚点 / 压制手 vs 包抄手），让群体执行**火力压制 + 机动**而非扎堆。
- **预告**——让上述一切清晰可见的动画与语音。

### 用途与局限

这套栈给出可读、可调、爽快的战斗——单人与合作射击的默认方案。它的局限是手工编写 AI 的老问题：反应式、玩家摸清后可被利用；掩体系统需要良好编写的掩体点（或昂贵的运行时掩体生成）；真正新颖的战术要么靠煞费苦心的编写，要么靠学习。完全学习式的 FPS 战斗智能体在研究中存在，但在上线游戏中罕见——部分因为机器的超人枪法太容易了，必须被*移除*才好玩。

### ▶ 运行它

[`samples/fps/tactical_fps.py`](../samples/fps/tactical_fps.py)——一个二人小队对据守玩家执行**火力压制 + 机动包抄**：**锚点**占据射击位并**压制**（把玩家钉住，玩家只盯着眼前可见威胁），而**包抄手**用一条**规避视线的路径**绕到不同方位完成击杀。视线、掩体、压制、包抄——整条 Doom → F.E.A.R. → 现代 的链路，浓缩在一个可运行文件里。

## 12. 策略 AI——文明、红色警戒与星际争霸

策略游戏要求任何类型中最广的 AI：一个对手必须同时管理**经济**、选择**建造顺序与科技路线**、部署**军队**，并在战斗中做**战术**决策——常常还横跨一张巨大地图。没有单一算法；有的是一**叠管理器**，每个都是第二部分里的经典技术。

### 回合制 4X：《文明》

《文明》AI 首要靠**效用 AI**（第 5 章）。每回合，为每座城市把它能造的一切按帝国当前需求打分选最高；在帝国层面则为科研、外交、以及在哪定居或开战打分。再配上单位寻路、前线用的影响力图和简单的战斗规则，你就有了一个 4X 对手。

**《文明》难度的公开秘密。** 这是每个策略玩家都该明白的事。在更高难度下，《文明》AI **并非更聪明——它获得加成**：额外起始单位、更便宜的建筑与单位、生产与科研加成、幸福 / 维护折扣，以及更强侵略性。决策逻辑跨难度基本**相同**；高难度只是塞给 AI 一份对它有利的**资源让步**。这是多数策略游戏难度务实的真相：真正*更聪明*的战略 AI 极难编写（状态空间是天文数字，推理是长时程的），于是工作室用加成来提供挑战。它有效、可预测、廉价——尽管老手会抱怨“AI 作弊”。

### 即时战略：《命令与征服》/《红色警戒》

经典 RTS AI（《C&C》《红色警戒》《魔兽争霸》《帝国时代》）是每帧运行的一组管理器：

- **经济管理器**——派采矿车采集资源；保持电力为正（缺电会跳闸）；扩建精炼厂。
- **建造顺序 / 科技管理器**——一条优先级策略：“我最缺什么？”先建电力，再经济，再解锁所选兵种的科技建筑。
- **生产管理器**——按生产能力（真实的生产队列）逐个产出作战单位，于是军队渐进增长。
- **战术管理器**——攒够军队后以**攻击波**投入；每次交战都消耗军队，于是重建、再攻。

而且，恰如《文明》，**经典 RTS AI 也“略微作弊”**——在更难的难度下它获得资源加成，并常常拥有**全图视野**（不用侦察就能“看到”你的基地），因为让 AI 公平地在战争迷雾下做战略太难写了。《红色警戒》的遭遇战 AI、《帝国时代》的电脑玩家、《星际争霸》的内置 AI 都倚赖这类让步。

有趣的设计后果是，RTS AI 是一个**平衡问题**：速攻路线（廉价单位、早期压力）与经济路线（贪婪扩张、攀科技到强力单位）在不同调校下互有胜负。看两者相撞、并意识到胜负是一个调参问题而非智力问题，是感受工作室为何在其上耗费如此之久的最佳方式。

### 前沿：《星际争霸 2》与 AlphaStar

《星际争霸 2》是策略 AI 的圣杯：实时、隐藏信息（战争迷雾）、巨大动作空间，以及一个早期经济选择在十分钟后才见分晓的长时程规划。手工编写 AI 远在专家人类水平之下就会停滞。2019 年，DeepMind 的 **AlphaStar**——深度强化学习加模仿学习引导与联赛式自我对弈（第 14 章）——达到了**宗师**级，跻身人类前百分之几。它是策略类里对应 Sophy 与 OpenAI Five 的存在：经典工具箱无法完全攻克、最终由学习攻克的难题。

### 用途与局限

管理器栈是几乎所有上线策略游戏构建 AI 的方式：透明、可调、快到能带上千单位。它的局限很真实——战术 AI 常是薄弱环节（平庸的军队微操、可被利用的进攻套路）、长时程战略很浅、难度倚赖加成而非技巧。学习式策略 AI（AlphaStar）能达到高得多的水平，但训练贵得惊人，而且像所有超人智能体一样，必须被*调低*才成为一个令人愉快的对手。

### ▶ 运行它

- [`samples/strategy/civ_ai.py`](../samples/strategy/civ_ai.py)——一个 4X 帝国 AI，用**效用打分**建造每座城市、研究科技树并扩张——并直接演示难度加成的真相：让**同一套大脑**分别以公平的“国王”帝国与获加成的“神级”帝国运行，你会看到决定胜负的是*让步*而非智力。
- [`samples/rts/command_conquer_ai.py`](../samples/rts/command_conquer_ai.py)——一场《红警》式遭遇战：**步兵速攻**路线对阵**经济 → 坦克**路线，各自是一整套经济 / 建造顺序 / 生产 / 战术管理器，胜负取决于调校——RTS 平衡难题的缩影。

## 13. 开放世界 AI——GTA、流式加载与性能预算

开放世界游戏——《侠盗猎车手》（GTA）、《荒野大镖客》、《赛博朋克 2077》、《刺客信条》——提出了一个别的类型没有的问题：它们必须让一**整座活着的城市**显得真实，同屏可见成百上千的行人、车辆与动物，且地图无缝到你能开车穿越十分钟而不见一次读盘。本章以 *GTA* 系列为范例（因为它是开放世界 AI 的决定性展示），回答四个问题：NPC 如何设计，如何把一个巨大世界与庞大人群塞进固定的内存与帧预算，生成式 AI 能否在其中生存，以及你如何在所添加的任何 AI 与性能之间取得平衡。

### NPC 如何设计

关键的认识是：一个 *GTA* 人群并不是成百上千个手工摆放的角色，而是一套**人口系统（population system）**，它持续地**在玩家周围生成 NPC，并在视野之外销毁它们**，任一时刻只保留有限数量“活着”。在哪生成、生成什么，由区域（海滩、商务区、贫民窟）、时段与一个**密度预算**驱动。沿街走去，你前方的行人正在你视野外被创建、又在你身后被悄悄删除——这座城市是一个维持在你周围气泡里的幻觉。

每个行人（“ped”）与车辆都运行一套由第二部分技术构建的、手工编写的决策架构：

- **分层任务系统。** Rockstar 的 RAGE 引擎用一棵**任务（task）**之树驱动行人（游荡、过马路、逃跑、进掩体、上车）——本质上是行为树 / HTN 的混合，一个高层任务展开为子任务。这就是第 4 章的 FSM / 行为树材料，被放大了。
- **场景（Scenarios）。** 世界被播撒了**场景点**——一些注解，说“这里的行人可以坐这张长椅 / 靠这面墙 / 扫地 / 晒太阳 / 喝咖啡”。环境 NPC 认领附近一个场景并演出其编写好的行为，这就是城市看起来*有目的*、而非满是漫无目的行走者的原因。场景是一种世界烘焙的效用：廉价、设计师编写、与地点绑定的行为。
- **两张图上的导航。** 行人在**导航网格**（第 7 章）上寻路；车辆跟随一张**道路 / 路径节点网络**——一张带速度、连接与路口的车道节点图——其上再叠加跟车、变道与遵守红绿灯。
- **感知与事件系统。** 行人有感官（视锥、听觉）与一个**事件队列**。枪声、冲上人行道的车、或一记拳头会生成一个事件，用更高优先级的反应**打断**当前任务——逃跑、蜷缩、还击，或报警。这种事件驱动的打断，正是让世界感觉有反应的原因。
- **通缉（Wanted）系统。** 警察是游戏的招牌战斗 / 追捕 AI：响应随通缉星级升级，警官向你寻路、使用掩体战斗（第 11 章），并在失去你的视线时切换到围绕你**最后已知位置**的**搜索**行为——恰是第 7 章“何时重规划 / 他们去哪了”的问题。

这一切都不是某个聪明的算法，而是**经典工具箱，被整合并预算化**——这才是开放世界 AI 真正的一课。

### 把巨大世界与庞大人群塞进固定预算

一台主机的内存固定、每帧约 16 毫秒。一张 *GTA* 地图大到无法装进内存，潜在智能体也多到无法每帧模拟。四个想法让它成为可能，它们是开放世界工程的核心：

1. **流式加载（Streaming）。** 世界被切成单元 / 区块，资产——几何、贴图、碰撞、音频与 AI 数据——**随玩家移动从磁盘流入内存**，而身后离开的单元被逐出。任一时刻只有玩家周围的一片区域驻留内存。一个专门的**流式系统**根据你的位置与速度预测你接下来需要什么，并及时加载，这就是地图没有读盘画面的原因。
2. **细节层次（LOD）——用于几何*与* AI。** 玩家附近，城市是全细节的、NPC 被完整模拟。更远处，几何降为更廉价的 **LOD 模型**、最终降为平面贴片；而且——关键地——**AI 也按“细节层次”运行**。这套 **LOD AI** 是最重要的一个想法：一辆远处的车不是一辆完整物理与 AI 的车，而是一个沿路径节点滑动的廉价“傀儡”；一群远处的人群是几个动画广告牌。完整模拟只花在玩家真正能感知到的地方。
3. **时间分片（Time-slicing）。** 即便近处的 NPC 也不是每帧都更新。它们的 AI 更新被**分摊到多帧上**——每帧只有一部分智能体按轮转日程“思考”，远处的思考更少。这把一笔付不起的“N 个智能体 × 每帧”变成一个固定的每帧成本。
4. **密度上限与剔除。** 硬性**上限**限制同时活跃的行人 / 车辆数量（按区域、按平台调校），空间划分加遮挡剔除让查询与渲染保持有界。人口系统生成到上限为止，不再多生成。

合起来看：**在玩家周围流入一个世界气泡，只对近且可见的东西做全保真模拟，其余一切用 LOD 造假，再把剩余工作分摊到多帧上。** 这就是一座“活着的城市”如何塞进固定预算。

### 我们能在开放世界里用生成式（LLM）AI 智能体吗？

能——但不是人们最初想象的那样。你**不能**为整座 *GTA* 人群运行 LLM：每分钟有成百上千个 NPC 生成与销毁，*每个 NPC 每句话*一次网络往返与按 token 计费在延迟和金钱上都不可能，而且会彻底打破人口 / 流式模型。现实的架构是**分层且混合**的：

- **大多数 NPC 保持经典。** 环境行人保留其廉价的任务 / 场景 AI——它们不需要语言。
- **少数“主角”NPC 用生成式 AI。** 一个任务角色、一个反复出现的店主、一个同伴——一小撮重要角色——可以用 LLM 驱动做开放式对话，正是第 16 章的人设 + 记忆 + 工具模式。
- **把 LLM 当离线内容工具用。** *提前*生成吆喝、环境闲聊与任务文本，审校后**烘焙进去**——你得到生成式的*多样性*，却零运行时成本与风险。
- **按需选型。** 一个小的**端侧**模型能以低延迟服务许多近处 NPC；一个大的**云端**模型留给少数值得的角色。**积极缓存**（相同情形复用回应）。
- **用工具限定 LLM 的权限。** 如第 16 章所述，让角色自由*说话*，但只通过一小组经校验的游戏函数*行动*——于是它永远无法破坏模拟、经济或分级。

阻碍与别处相同：延迟、规模化成本、与正史的一致性、供 QA 的确定性，以及内容安全。**NVIDIA ACE**、**Inworld AI**、**Convai** 等中间件的存在，正是为了让“少数可对话 NPC”这一层变得可行；而 mod 已经把 GPT 驱动的 NPC 放进了 *GTA V* 作为概念验证。

### 在你所添加的 AI 与性能之间取得平衡

上述每一项技术其实都是同一门纪律：**把帧预算花在玩家会注意到的地方，别处一分不花。** 当你给游戏添加*任何* AI——更聪明的敌人、一个学习式策略、一个 LLM 同伴——都用同一套打法：

- **给 AI 一个帧预算。** 一开始就定下 AI 可用比如 16 毫秒里的 2–3 毫秒，并据此设计、据此剖析。
- **按重要性与距离分层（LOD AI）。** 为屏上、与玩法相关的智能体配完整大脑；其余用廉价近似或干脆不配。这一个想法买到的最多。
- **时间分片并错峰。** 别每帧运行每个智能体；把昂贵决策（规划、重寻路、推理）摊到多帧、跨多个智能体。
- **异步、离主线程。** 在工作线程上、或落后一两帧运行寻路、规划与模型推理，于是一次峰值永不卡住渲染。
- **缓存与预计算。** 离线烘焙导航网格、影响力图与掩体点；记忆化计划与 LLM 回应；在相似智能体间复用结果。
- **对学习式模型，选型并批处理。** 量化并在端侧运行小模型；**批量**推理调用；以低于渲染循环的频率运行。对 LLM NPC 尤其：流式输出 token 让对话*快速开始*，限制上下文长度，并优先“多次调用小模型”而非“少次调用巨型模型”。
- **优雅降级。** 预算吃紧时（一场大枪战、一个密集人群），*降低 AI 保真度*——更少思考的智能体、更简单的行为——而不是掉帧。玩家原谅稍显呆板的远处人群；他们不原谅卡顿。

从《Doom》的状态机到一个假想的 LLM 驱动 *GTA* 同伴，贯穿始终的是同一条：**让你所付出的智能，匹配玩家实际能给予的注意力。**

### ▶ 看它

交互式配套包含一个**开放世界 AI** 视图，正好把这一切可视化：玩家位于同心的 **LOD-AI 环**中心（全模拟 → 简化 → 流出），NPC 在你附近生成、在远处销毁，对着一个**密度上限**，还有一个你能推动的实时**帧预算表**——通过加大全模拟半径或切换“LLM 主角 NPC”，实时观察成本与优雅降级。

# 第四部分——现代学习式 AI

第四部分的技术从经验或数据中**学习**行为，而非手工编写。它们解决经典工具箱确实无法解决的问题——但代价是数据、算力与可预测性，这正是它们补充而非取代经典技术的原因。

## 14. 强化学习

在**强化学习（RL）**中，智能体通过**试错**来最大化累积**奖励**。它只凭来自环境的奖励信号构建一个**策略**——从状态到动作的映射——没有任何“正确”玩法的示例。奠基算法是 **Q-learning**，它学习一个值 **Q(s, a)**——在状态 *s* 采取动作 *a* 的长期期望回报——通过如下更新：

```
Q(s,a) ← Q(s,a) + α · [ r + γ · maxₐ' Q(s',a') − Q(s,a) ]
```

其中 **α** 是学习率，**γ** 折扣未来奖励。把 Q 存成表格用于小问题；把表格换成**神经网络**，就得到**深度 Q 网络（DQN）**。像 **PPO** 这样的策略梯度方法，加上**自我对弈**（智能体与自己的副本对练），驱动了那些标志性成果：

| 系统 | 年份 | 游戏 | 方法 |
|------|------|------|------|
| **AlphaGo / AlphaZero / MuZero** | 2016– | 围棋、国际象棋、将棋 | 深度 RL + MCTS，自我对弈 |
| **OpenAI Five** | 2019 | 《Dota 2》 | PPO 自我对弈，5 智能体团队 |
| **AlphaStar** | 2019 | 《星际争霸 2》 | RL + 模仿 + 联赛式自我对弈 |
| **GT 赛车 Sophy** | 2022 | 《GT 赛车》 | 带塑形奖励的深度 RL |

**用途。** 超人或高度自适应的对手；为过于复杂而无法脚本化的游戏（赛车物理、RTS/MOBA 微操）打造智能体；自动化**试玩与平衡**；调优 NPC 技能。RL 在你拥有一个**快速模拟器**和一个**清晰奖励**时效果最好。

**局限——而且很严重。**
- **样本饥渴且昂贵。** OpenAI Five 每天训练相当于*数百年*的游戏时长；几乎没有工作室负担得起这样的算力。
- **奖励设计很危险。** 一个指定糟糕的奖励会导致**奖励作弊**——智能体钻空子而非“正常”地玩（例如一个划船竞速智能体学会原地转圈刷分而非完成比赛）。
- **不可预测且难以调试。** 学到的策略是一个黑箱；你很难保证它在从未见过的情形里不会做出荒唐的事。
- **常常*太强*。** 超人机器人并不好玩。上线的 RL 对手（如《GT 赛车 7》里的 Sophy）必须被**刻意削弱与调校**才有趣。
- **集成成本高。** 它需要训练管线、模拟器和繁重的 QA——相比状态机是一笔巨大投入。

- [`samples/rl/sophy_racing_qlearn.py`](../samples/rl/sophy_racing_qlearn.py)——同一算法用于*驾驶*：没有任何预设赛车线，智能体学会一套弯前刹车、直道加速的速度曲线——Sophy 的核心思想在教学尺度上的再现。

## 15. 模仿学习与其他机器学习

并非所有学习式 AI 都由奖励驱动。**模仿学习（行为克隆）**训练一个模型从录制的数据中*复制人类玩法*——没有奖励函数，只有示例。著名的上线例子是**《极限竞速》Drivatar**：它从玩家的圈速中学习*个人*的驾驶风格，于是你朋友的 AI“幽灵”即便离线也带着他们真实的习惯与怪癖参赛。结果是**拟人化**对手（连失误一起），这往往比 RL 智能体那完美无瑕的线路更好玩。

其他机器学习在从不充当“对手”的情况下悄悄塑造着游戏：
- **学习式动画**——动作匹配与神经移动控制器从庞大素材库中挑选或混合动画，实现自然移动。
- **玩家建模**——流失预测、匹配、技能评分与动态难度。
- **作弊与毒性检测**、**QA / 试玩机器人**，以及 **PCGML**（机器学习式内容生成）。

务实的前沿是**混合系统**：用行为树搭结构、用效用打分做决策、用学习式子策略处理困难的运动技能（瞄准、驾驶）、用影响力图做战术、用 LLM 做对话——*每种技术都用在它最擅长之处*。没有一款严肃的游戏是“全经典”或“全学习”的。

## 16. 生成式 AI 智能体（LLM）

最新的游戏 AI 类型把一个**大语言模型（LLM）**置于一个角色或智能体的核心。NPC 不再依赖固定对话树，而是拥有：

- 一个**人设**——定义它是谁、它的知识与它的声音的系统提示词；
- **记忆**——近期对话，有时还包括可检索的长期记忆库；
- **工具 / 函数调用**——让它的话语转化为*真实的游戏动作*：发布任务、开启商店、改变好感度、移动、攻击。

玩家现在可以说**任何话**，NPC 都会符合人设地回应并作用于世界。再把许多这样的智能体放进一个共享世界，**涌现式社交行为**便会出现。奠基性的演示是**《生成式智能体》**（Park 等人，斯坦福，2023）：沙盒小镇“Smallville”里的 25 个 LLM 驱动智能体建立关系、传播消息，并自发组织了一场情人节派对——没有一处是脚本化的。**NVIDIA ACE**、**Inworld AI**、**Convai** 等中间件如今把带语音、LLM 驱动的 NPC 带入真实引擎。

**用途。** 开放式、可反复游玩的对话；动态任务；有个性与记忆的同伴；供无障碍设计的自然语言交互；以及——强大地——作为一个*离线设计工具*，生成随后被审校并烘焙进去的内容（吆喝、任务、传说）。

**局限。**
- **幻觉与一致性。** LLM 会编造事实、破坏世界观、自相矛盾——这对正史与叙事很危险。
- **可控性与安全。** 自由生成的输出可能跑调、被玩家利用（“越狱”），或说出工作室从未批准的话。必备的纪律是**用工具限定 LLM 的权限**：让它自由*说话*，但只通过一小组经校验的函数*行动*，于是它永远无法做游戏不允许的事。
- **延迟与成本。** 每句话一次网络往返增加延迟；按 token 计费在规模化时累积可观；端侧模型以质量换速度。
- **确定性与测试。** 非确定性输出难以 QA，也难以为 bug 报告复现。
- **落地（Grounding）。** LLM 必须通过工具与记忆绑定到真实游戏状态，否则它只是没有玩法后果的闲聊。

### ▶ 运行它

[`samples/generative/generative_npc.py`](../samples/generative/generative_npc.py)——一个 LLM 铁匠，既即兴生成符合人设的对话，**又**通过工具调用（发布任务、查看库存、调整好感度）驱动真实游戏状态。有 API 密钥时用 Anthropic 的 Claude（`claude-opus-5`），否则通过同一条代码路径运行一个完全**离线的模拟**，因此你可以零配置地研究其人设 / 记忆 / 工具架构。

# 第五部分——实践

## 17. 如何选择方案

没有“最好”的技术——只有在第 1 章约束下最适合某项具体工作的技术。把这当作一份入门决策指南：

| 如果你需要…… | 就选用 | 原因 |
|--------------|--------|------|
| 行为清晰、可编写的守卫 / 敌人 | **FSM / 行为树** | 可预测、廉价、设计师可控 |
| 在多种竞争需求间权衡的智能体 | **效用 AI** | 由可调分数产生平滑取舍 |
| 复杂、自适应的反应式战术 | **GOAP** | 从目标 + 行动涌现出计划 |
| 自然移动的群体 | **集群 / 转向** | 涌现式协调，无中央大脑 |
| 穿过地图抵达某点 | **A\* / 导航网格** | 最优、成熟 |
| 棋类 / 回合制游戏的强对手 | **Minimax + α-β，或 MCTS** | 最优前瞻 / 采样搜索 |
| 知道“谁控制哪里” | **影响力图** | 廉价的空间战术态势 |
| 可信的街机赛车对手 | **路点 + PID + 橡皮筋** | 接近、有趣、可控的比赛 |
| 无尽的关卡 / 地图 / 掉落 | **PCG** | 无限内容、可重玩 |
| 一个巨大的活世界与庞大人群 | **流式 + LOD AI + 时间分片** | 只为玩家能感知的部分付出算力 |
| 超人或无法脚本化的技巧 | **强化学习** | 学到你写不出来的东西——但有代价 |
| 从数据得到拟人化对手 | **模仿学习** | 复制真实玩家的风格 |
| 开放式对话与涌现式角色 | **生成式 / LLM 智能体** | 符合人设地说 / 做任何事 |

**经验法则。**
1. **从满足设计目标的最简单技术起步。** 一个你能发布的状态机，胜过一个你调不明白的神经网络。
2. **只有当手工编写确实不切实际时才动用学习**——超人技巧、无法脚本化的物理、开放式语言。
3. **用工具、校验与退回到编写行为的能力，限定每一个强力 / 生成式智能体。**
4. **预告一切。** 玩家只会把他能感知到的智能算作智能。
5. **为乐趣调校，而非为胜利。** 始终如此。

## 19. 术语表

- **A\***——最小化 `f = g + h` 的最佳优先寻路；在启发式可采纳时最优。
- **可采纳启发式**——从不高估剩余代价的启发式；A\* 最优性所必需。
- **行为树（BT）**——由序列 / 选择 / 动作节点构成、每帧重新求值的树；角色 AI 的 3A 标准。
- **Boids**——Reynolds 的集群模型：分离 + 对齐 + 聚合。
- **动态难度调整（DDA）**——悄悄把挑战调至玩家水平；橡皮筋是其一种形式。
- **有限状态机（FSM）**——状态 + 事件驱动的转移；最简单的决策技术。
- **流场（Flow field）**——预计算的方向场，一整群体跟随它奔向目标。
- **GOAP**——面向目标的行动规划；用带前置条件 / 效果的行动在世界状态上跑 A\*。
- **启发式**——引导搜索的估计（A\* 里的 `h`）。
- **影响力图**——概括空间控制 / 威胁、供战术决策的网格。
- **模仿学习**——训练模型复制录制的人类行为（如 Drivatar）。
- **视线（LOS）**——一点能否无遮挡地“看到”另一点；是大多数感知的闸门。
- **LLM**——大语言模型；生成式 NPC 的引擎。
- **LOD AI（细节层次 AI）**——对近 / 可见智能体做全保真模拟、对远处做廉价处理（或干脆不做）；开放世界规模的关键。
- **MCTS**——蒙特卡洛树搜索；用 UCB1 做选择 / 扩展 / 模拟 / 回传。
- **Minimax / Alpha-Beta**——最优博弈搜索 / 其剪枝优化。
- **导航网格（Navmesh）**——把可行走空间表示为凸多边形以高效寻路。
- **PCG / PCGML**——程序化内容生成 / 其机器学习变体。
- **PID 控制器**——比例-积分-微分控制；用于转向 / 速度。
- **策略（Policy）**——从状态到动作的映射；RL 智能体所学的东西。
- **人口系统**——围绕玩家生成 NPC 到密度上限、并在视野外销毁，在有界预算内造出“活着的”人群。
- **PPO / DQN**——近端策略优化 / 深度 Q 网络；深度 RL 算法。
- **纯追踪 / 前视**——朝路径上前方一点转向。
- **Q-learning**——学习 `Q(s,a)` 的值型 RL。
- **奖励作弊**——RL 智能体钻奖励的空子，而非达成预期行为。
- **橡皮筋（Rubber-banding）**——赛车里的 DDA：给落后 AI 提速、给领先者减速。
- **转向行为**——混合成移动的小而可组合的力（寻的、逃离、抵达、游荡……）。
- **流式加载（Streaming）**——随玩家移动从磁盘加载世界资产（几何、AI 数据）、逐出身后内容，让巨大地图装进固定内存。
- **压制（Suppression）**——用火力钉住目标以降低其效能、迫使其进掩体。
- **预告（Telegraphing）**——通过动画 / 音频让 AI 的意图清晰可见，使玩家感知到智能。
- **时间分片**——把智能体的 AI 更新分摊到多帧，而非每帧更新全部，以限定每帧成本。
- **UCB1**——MCTS 在选择阶段使用的探索 / 利用公式。
- **效用 AI**——用效用函数为动作打分并选最优；驱动《模拟人生》与 4X 生产。

# 附录 A——在引擎里训练 AI（Unity ML-Agents 与 Unreal Learning Agents）

第四部分的学习式技术——尤其是强化学习——引出一个显然的问题：示例用 Python 训练，但游戏用 **C#**（Unity）或 **C++**（Unreal）发布。一个模型是如何*用一款游戏*来训练、再*在其中*运行的？本附录回答这个问题，参考代码位于 [`../engine-integration`](../engine-integration)。

### 游戏即环境

训练一个智能体，是**智能体**与**环境**之间的一个循环——而在游戏里，*游戏就是环境*。你必须定义四件事——**智能体契约**——它们在每个框架里都一样：

- **观测（Observations）**——智能体感知什么（一个状态向量：我的位置、目标、我的速度……）。只放公平、可观测的信息。
- **动作（Actions）**——它能做什么（如一个二维移动力；离散的按键）。
- **奖励（Reward）**——定义“好”的标量（到达目标 +1，微小的时间惩罚，掉下去为 0）。
- **重置（Reset）**——如何开始新回合（重新放置智能体与目标）。

训练把这个循环跑上百万次；一个**策略**（神经网络）逐渐学会选择最大化奖励的动作。然后你**冻结**网络，在上线游戏里每帧只运行 `观测 → 动作`。最后这一步——推理——只是一次快速前向传播；所有学习都发生在离线阶段。

### Unity——ML-Agents（Python 训练，C# 运行）

Unity 的 **ML-Agents 工具包**有两半。在游戏内你写一个 C# `Agent` 子类，重写 `CollectObservations()`、`OnActionReceived()`（在这里也调用 `AddReward()` / `EndEpisode()`）与 `OnEpisodeBegin()`——这*就是*上面的智能体契约。训练由一个**外部 Python 进程**驱动（`mlagents-learn config.yaml`，基于 PyTorch 的 PPO），它通过 socket 连接 Unity：接收观测、返回动作、接收奖励，并在场景的众多并行副本上更新网络。它导出一个 `.onnx` 文件。

要**在游戏内运行**它有两种方式，都是纯 C#、运行时无需 Python：（1）把 `.onnx` 赋给智能体的 **Behavior Parameters → Model** 并设为 **Inference Only**——*同一个*智能体脚本照常运行，由 **Unity Sentis**（前身 Barracuda）来评估网络；或（2）你自己用 Sentis 加载 `.onnx` 并在自己的代码里做前向传播（这也是运行一个纯 PyTorch 训练模型的方式）。见 `engine-integration/unity/`。

### Unreal——Learning Agents（引擎内训练）+ NNE（推理）

Unreal 的 **Learning Agents** 插件走的是另一条路：训练用 C++ **在引擎内部**运行——*没有外部 Python 训练器*。你写一个 **Interactor**（定义观测与动作）、一个 **Trainer**（定义奖励与完成）、以及一个 **Policy**（网络）；每个引擎 tick 推进一步 PPO，通常把游戏加速并让许多智能体并行。推理时你去掉训练器，只跑 Interactor + Policy。另外，Unreal 的 **NNE（神经网络引擎）**在运行时加载并运行任意 **ONNX** 模型（Unity Sentis 的对应物）——因此一个 Python 训练的模型也能在 Unreal 游戏里运行。见 `engine-integration/unreal/`。*（Learning Agents 是实验性的，其 API 在不同引擎版本间会变。）*

### 训练中的人类反馈

除了固定的奖励函数，你还可以把**人放进训练回路**：训练时操作者按键实时奖励或惩罚它，这些信号折入优化器最大化的*同一个*奖励——这是 TAMER / RLHF 的一种简单形式。[`../engine-integration`](../engine-integration) 中两个完整项目都实现了这一点（Unity 的 `HumanFeedback.cs`；Unreal 的 `RollerManager` + `MoveTrainer`），并同时展示了从录制的人类演示中**模仿学习**（行为克隆 + GAIL）。Unity 示例是一个可导入的项目，运行时自建场景；Unreal 示例是一个完整的 C++ 项目脚手架。

### 一览

| | Unity ML-Agents | Unreal Learning Agents |
|---|---|---|
| 你写什么 | C# 智能体 + YAML | C++ / 蓝图 |
| 训练在哪运行 | 外部 Python（PyTorch） | 引擎内（C++ PPO） |
| 游戏内运行模型 | Sentis（原 Barracuda） | NNE |
| 运行 Python 训练的 ONNX | 是（Sentis） | 是（NNE） |
| 成熟度 | 稳定、广泛使用 | 实验性 |

全书的主线最后再回响一次：*算法*才是真正的内容；*语言*只是交付方式的选择——用 Python 学它，用 C#/C++ 发布它，以及（如本仓库的交互实验室）用 JavaScript 演示它。
